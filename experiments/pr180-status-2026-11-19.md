## What the evaluation found

All numbers are from LaMAria 800-frame windows, 3 runs per config, `--no-pace`, on a laptop. This is a quick check, not the benchmark: R_01 and R_03 are easy, R_11 is medium.

- **`pr180-frontend-1ms` is the best preset tried on these windows.** It scores R_01 0.10 m against `lamaria-rig-imu`'s 0.59 m. On the full R_01 sequence it tracks 100 %, but with ATE 1.18 m and scale 1.136, so drift is still the score gap (ledger G18).
- **Card H (G30).** `tracking.pose_inertial: OrbSlam3`, card A6 and the idea of PR #195, collapses scale on R_01. On rejected frames, solve inliers / visual inliers are 0.09-0.12. It is now off in `pr180-full`.
- **Card I (G31).** R_11 loses its first map at frame 3. The cold start then waits about 120 frames for 50 stereo points; the pinhole-cropped rig gives p50 21. Lowering the minimum to 20 fixes R_11, but breaks R_03.
- **Card J (G32).** Why R_03 breaks under that minimum:
  - The map is seeded one frame earlier, inside the camera's auto-exposure ramp.
  - VIBA0 comes out 3.4° off, against 0.47° for the base.
  - VIBA2 then fits a systematic tilt of about 14° (|ba| 2.3-2.7 m/s², same direction in 10/10 runs) and is rejected, and tracking is lost.
  - Excluding the keyframes inserted while lost (J4) and gating outlier edges (J1) were both tested and refuted.
  - R_03, like R_01, has no factory calibration, so its IMU is not rectified. That is a candidate part of the cause.
- **Frontend speed (G33).** The frontend p50 is about 10 ms, not 1 ms: KLT's `keyframe due` over-fires, and 76 % of frames run ORB.

The owner's target is 100 % tracking on the easy and medium sequences.
- **Current best:** R_01 800/800 and R_03 777-788/800 with `pr180-frontend-1ms`; R_11 668/800 with it, and 800/800 only with `min_cold_start_points: 20`, which breaks R_03.
- **Left to do:** fix G32, then ship `min_cold_start_points: 20`.

## How to rerun

The scripts are in `experiments/quick-eval/`. Set `LAMARIA_DATA` to the root that holds `<seq>/asl/<seq>`, `<seq>/pinhole_calibrations` and `<seq>/ground_truth/pseudo_dense`. Set `LAMARIA_FACTORY` to the folder of `<seq>.factory.json` files (optional; LaMAria ships them for R_11 and the `sequence_*` sequences only). Set `VOCAB` to `ORBvoc.txt`.

```bash
cargo +1.100.0 build --release -j2 -p kornia-slam-app        # binary: target/release/kornia-slam
Q=experiments/quick-eval
$Q/make_config.sh configs/pr180-frontend-1ms.ron R_03_easy /tmp/r03-J41.ron \
  'tracking_loss: ( reseed: ( min_cold_start_points: 20 ) ),' \
  'inertial: ( viba_window: VisualOnly, viba_velocity_gate: 10.0 ),'
$Q/run.sh target/release/kornia-slam /tmp/out 3 /tmp/r03-J41.ron   # 3 runs, at most 3 at once (JOBS)
$Q/score.sh /tmp/out                                                # tracked, coast, give-ups, ATE SE3, scale, VIBA lines
```

- **Runs are not deterministic.** Trajectory `cmp` therefore fails, and a knobs-off check compares the printed VIBA numbers instead. Use 3 runs per config.
- **Run time:** an 800-frame run takes a few minutes, and the laptop limit is 3 at once at `-j2`.
- **Sequence windows:** `score.sh` picks the sequence from the run-dir prefix (`r01`, `r03`, `r11`), or from `SEQ`.
- **Ground truth:** it is pseudo-dense and covers only part of the R_11 window. Use `[summary] tracked` for coverage, and ATE only for accuracy.
